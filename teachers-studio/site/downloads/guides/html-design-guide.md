# עיצוב ויצוא דרך HTML

משל: מסמך שבנוי כ־HTML הוא כמו כיתה שאפשר להזיז בה שולחנות ולשנות שלטים. תמונה סופית (PDF, JPG) היא צילום של הכיתה. מצלמים רק כשמרוצים מהסידור.

## התהליך
1. מגדירים תוכן, קהל ושפה עיצובית (צבע מותג, גופן, לוגו).
2. מבקשים מה־AI קובץ HTML עם מבנה מסודר ועיצוב שאפשר לשנות (משתני CSS).
3. מבקשים שינויים ממוקדים, אחד בכל פעם: ״הגדל את הכותרות״, ״הוסף מקום לתשובה בשאלה 3״.
4. בודקים קריאות, דיוק והדפסה (תצוגה מקדימה להדפסה בדפדפן).
5. מאשרים ומייצאים.
6. שומרים את קובץ ה־HTML המקורי לעריכה בעתיד.

## בקשה להעתקה
```text
הכן לי [דף עבודה / הזמנה / מסמך] כקובץ HTML יחיד ושלם בעברית (lang="he" dir="rtl").
תוכן: [הדביקו או תארו]. קהל: [ ]. סגנון: [צבע מותג, גופן, לוגו אם מצורף].
דרישות: צבעים, גופנים וגודל כתב כמשתני CSS ב־:root. כללי @media print עם @page A4 ושוליים.
בלי שבירת עמוד באמצע שאלה או טבלה. בלי קבצים חיצוניים. אל תייצא ל־PDF, אבדוק בדפדפן.
בסבב הראשון: מבנה ותוכן בלבד. בסבבים הבאים אבקש שינויים ממוקדים.
```

## כללי הדפסה בסיסיים
```css
@page { size: A4; margin: 12mm; }
html { direction: rtl; }
.question, table { break-inside: avoid; }
* { -webkit-print-color-adjust: economy; print-color-adjust: economy; }
```

## ייצוא: מה אפשר ומה לא
| פורמט | איך | מגבלות |
|---|---|---|
| PDF | הדפסה מהדפדפן ← שמירה כ־PDF | לבדוק חלוקת עמודים בתצוגה מקדימה |
| JPG או PNG | צילום מסך או כלי ייצוא מתאים | זה צילום: לא ניתן לעריכה בהמשך |
| Word | HTML פשוט ותואם, או בקשה ליצירת DOCX | Word אינו משמר תמיד עיצוב HTML מורכב |
| RTF | רק כקובץ RTF תקין | לבקש במפורש ולפתוח לבדיקה |
| MP4 | רינדור או הקלטת מסך | אנימציית HTML אינה קובץ וידאו |

## על חיסכון בטוקנים
מקור מובנה (HTML עם משתנים) מקל על שינוי ממוקד, כי אפשר לבקש לשנות משתנה אחד במקום לכתוב הכול מחדש. זה לא מבטיח חיסכון בטוקנים בכל מצב.
